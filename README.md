# VPN: подписки и заявки в Telegram

Рабочая первая версия на Python + SQLite. Админка находится внутри Telegram, доступна только ID из `ADMIN_IDS` в личной переписке с ботом. Тарифы: **1400 ₽ за месяц, 4137 ₽ за 3 месяца, 8148 ₽ за 6 месяцев, 15792 ₽ за 12 месяцев**. Сроки считаются календарными месяцами. Например, месяц с 31 января заканчивается 28/29 февраля; последующее продление считается от этой даты.

## Что реализовано

- Клиент выбирает срок и оплачивает через страницу RollyPay.
- Только подтверждённая оплата создаёт тикет и уведомляет администраторов.
- Администратор берёт заявку, вручную создаёт VPN и отправляет ссылку через бот.
- Первая подписка начинается при выдаче; действующая продлевается от окончания, истёкшая — от выполнения заявки.
- Продление VPN выполняется вручную на сервере, затем подтверждается кнопкой «Продление выполнено».
- Ссылка и срок доступны в «Моя подписка». Клиент видит свои заказы и может повторно открыть оплату.
- В админке можно добавлять, редактировать, включать и отключать варианты срока/цены. Цена и срок сохраняются в заказе; изменения тарифа не меняют существующие заказы.
- Текстовая поддержка с ответом через бота. Сообщения сохраняются в базе. Файлы пока не поддерживаются.
- Напоминания примерно за 3 дня, за сутки и после окончания (проверка раз в час). Администратор получает уведомление для ручного отключения VPN.
- Уведомления хранятся в очереди и повторяются при сбоях Telegram. Если Telegram принял сообщение, но ответ потерялся, возможен повтор уведомления; повторной выдачи подписки не будет.
- Проверка подписей RollyPay, суммы, валюты, номера заказа, режима тестирования. Повторные события не создают повторных тикетов/продлений. Возвраты блокируют невыполненные тикеты и уведомляют администратора для ручной корректировки VPN.

Лимит 10–15 устройств задаётся вами на VPN-сервере. Бот не создаёт VPN, не проверяет работоспособность ссылки и не управляет устройствами. Автосписаний нет: каждое продление клиент оплачивает отдельно.

## Запуск на сервере через Docker

Понадобятся Linux-сервер с Docker Compose, домен с HTTPS, токен BotFather, числовой Telegram ID администратора и касса RollyPay (`api_key`, `signing_secret`). Секреты не отправляйте в чат и не храните в репозитории.

1. Скопируйте `.env.example` в `.env` и заполните значения. Несколько администраторов: `ADMIN_IDS=123456789,987654321`. Оставьте `ROLLYPAY_TEST=true` для первой проверки.
2. Запустите:

   ```sh
   docker compose up -d --build
   docker compose logs -f --tail=100
   ```

3. На существующем HTTPS reverse proxy направьте `/webhooks/rollypay` на `http://127.0.0.1:8080/webhooks/rollypay`. Например, Caddy на том же сервере:

   ```caddy
   bot.example.com {
       reverse_proxy 127.0.0.1:8080
   }
   ```

   Замените домен своим, настройте DNS и доступ к портам 80/443. Внешний HTTPS нужен для RollyPay; Telegram работает через long polling.
4. В настройках кассы RollyPay укажите `callback_url=https://bot.example.com/webhooks/rollypay`. Настройку можно выполнить через поддержку или API кассы. Нельзя начинать реальные продажи до проверки доставки этих уведомлений.
5. Каждый администратор должен открыть бот и нажать `/start`: иначе бот не сможет первым написать ему. Меню администратора открывается кнопкой или `/admin`. `/id` показывает ваш числовой ID; при необходимости обновите `ADMIN_IDS` и пересоздайте контейнер.
6. Пройдите тестовый платёж и ручную выдачу. Тестовые заявки помечаются `[ТЕСТ]` и **не добавляют реальный срок подписки**.
7. После проверки установите `ROLLYPAY_TEST=false` и выполните `docker compose up -d --force-recreate`.

Telegram webhook не должен быть установлен: если установлен, запуск завершится с объяснением. Используйте отдельного бота или предварительно удалите прежний webhook. Запускайте один экземпляр приложения; блокировка файла предотвращает одновременную работу с одной базой.

Данные сохраняются в Docker volume `bot-data`. Не используйте `docker compose down -v`, если хотите сохранить клиентов и подписки. База содержит персональные VPN-ссылки: ограничьте доступ к серверу и резервным копиям.

## Сценарий администратора

- «Админка → Управление тарифами → Добавить».
- Формат сообщения: `VPN — 3 месяца | 3300 | 3`.
- Для изменения используйте кнопку «Изменить» у нужного варианта. Срок задаётся целым числом календарных месяцев от 1 до 60.
- «Оплаченные заявки → Открыть → Взять в работу».
- Создайте VPN, выберите «Выдать / заменить ссылку» и отправьте ссылку одним сообщением.
- Для продления сначала продлите доступ на VPN-сервере, затем нажмите «Продление выполнено» и подтвердите действие. Старая ссылка сохраняется.
- `/cancel` отменяет текущий ввод. `/start` возвращает главное меню.

## Если создание платежа завершилось тайм-аутом

Чтобы не создать второй платёж, бот сохраняет заказ в `uncertain`, блокирует новую покупку и уведомляет администратора.

Откройте «Проверить зависшие оплаты», найдите `order_id` в RollyPay. Если платёж есть, используйте `/recover order_id payment_id`: бот сам сверит данные по API. Если API не возвращает поле `test`, запросите повторную доставку подписанного вебхука через поддержку RollyPay. Подделывать вебхуки или вручную менять статус на `paid` не нужно.

Если проверка в RollyPay подтвердила, что платёж не был создан, используйте `/close_unpaid order_id` и подтвердите фразой `НЕ СОЗДАН`. Клиент сможет повторить покупку. История сохранится, позднее подтверждение оплаты всё ещё будет обработано.

Кнопка «Проверить оплату» сверяет платёж через API. Если API не возвращает признак тестового режима, подтверждение ожидается через подписанный вебхук. Следите за доставкой уведомлений в RollyPay; после длительного простоя может потребоваться повторная доставка. Автоматической полной сверки всех платежей в этой версии нет.

Возврат денег выполняется в RollyPay, а не кнопкой бота. Бот обрабатывает результат возврата, блокирует заявку и уведомляет вас. При уже выданном подключении отключение/корректировка срока на VPN-сервере и урегулирование с клиентом выполняются вручную.

## Локальная разработка и тесты

Python 3.9+ (Docker использует 3.12), Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

При запуске без Docker экспортируйте переменные из `.env.example`, заменив `DATABASE_PATH` на `data/bot.sqlite3`, `HOST` на `127.0.0.1`. Приложение само файл `.env` не читает; Compose читает его через `env_file`.

```sh
python3 -m vpn_bot.app
```

Тесты используют временные локальные HTTP-серверы, имитирующие Telegram и RollyPay; реальные платежи не создаются. Проверяются порядок «оплата → тикет → выдача», права администратора, подписи, защита от дублей, возвраты, тестовый режим, продления, тарифы, напоминания, поддержка и восстановление зависшего платежа. Реальный обмен с вашей кассой нужно проверить отдельно после настройки секретов.

Для резервной копии работающей базы используйте SQLite backup API (не копируйте только файл базы при работающем WAL):

```sh
docker compose exec bot python -c "import sqlite3; src=sqlite3.connect('/app/data/bot.sqlite3'); dst=sqlite3.connect('/app/data/backup.sqlite3'); src.backup(dst); dst.close(); src.close()"
docker compose cp bot:/app/data/backup.sqlite3 ./backup.sqlite3
```

Храните резервные копии в защищённом месте вне сервера. Перед восстановлением остановите приложение.

## Ограничение Telegram

Интеграция RollyPay технически реализована по предоставленной документации. Telegram требует Stars для продажи цифровых услуг внутри ботов; внешняя платёжная ссылка сама по себе не отменяет это требование. Наличие этой реализации не означает, что продажа VPN через RollyPay внутри Telegram разрешена правилами платформы. До публичного запуска необходимо определить допустимую схему продаж.

Документация:
- https://docs.rollypay.io/getting-started/
- https://docs.rollypay.io/api/authentication/
- https://docs.rollypay.io/api/payments/
- https://docs.rollypay.io/api/callbacks/
- https://core.telegram.org/bots/payments-stars

## Локальная демонстрация без кассы

`DEMO_MODE=true` вместе с `ROLLYPAY_TEST=true` включает имитацию оплаты. Нужны только `BOT_TOKEN` и `ADMIN_IDS`; используйте отдельную базу `DATABASE_PATH=data/demo.sqlite3`. Заказ отправляет администраторам кнопку «Имитировать оплату». Клиенты не могут нажать её, в обычном режиме обработчик отключён. Реальные платёжные запросы не создаются, входящие вебхуки отключены, выдача не меняет реальные подписки.

`python3 -B run_local.py` загружает настройки из локального `.env`. Тестовая копия работает, пока компьютер включён и имеет доступ в интернет. Для постоянного запуска используйте сервер по инструкции выше. Перед реальной работой отключите `DEMO_MODE`, настройте ключи RollyPay и отдельную базу.

## Страны подключения

После выбора тарифа новый клиент выбирает страну перед оплатой. Она сохраняется в заказе, уведомлении администратора и выданной подписке. При продлении сохраняется прежняя страна, даже если она скрыта для новых клиентов. Старые заказы без страны остаются доступны.

«Админка → Локации» позволяет добавить страну или включить/отключить её для новых подключений. В обычном режиме список изначально пуст: добавьте реальные доступные страны. В демо автоматически добавляются Германия, Нидерланды и Финляндия для проверки интерфейса; это не подтверждение наличия серверов.

## Расчёт тарифов

Уточнённая база пользователя: аренда = 700 ₽/месяц, цена клиенту = 1400 ₽/месяц. Цена без скидки — аренда 700 ₽ + наценка 700 ₽ за каждый месяц. Скидка провайдера применяется только к аренде: `700 × месяцы × (1 − скидка) + 700 × месяцы`.

- 1 месяц: 1400 ₽.
- 3 месяца, скидка на аренду 3%: 4137 ₽.
- 6 месяцев, скидка на аренду 6%: 8148 ₽.
- 12 месяцев, скидка на аренду 12%: 15792 ₽.

Используются проценты со скриншота, а не обратный пересчёт округлённых долларовых сумм. Это заданная база расчёта, не текущий валютный курс. Скидка на итоговую клиентскую цену составляет соответственно 0%, 1,5%, 3% и 6%.

Однократное обновление исправляет ранее рассчитанные цены на новые и добавляет недостающие сроки. После этого изменения из админки сохраняются при перезапусках. Существующие заказы сохраняют исходные суммы и сроки.

## Комиссия платёжной системы

Комиссия RollyPay — 9% от клиентского платежа по данным владельца. Она удерживается из текущей цены, дополнительно к цене не начисляется. Тарифы остаются 1400 / 4137 / 8148 / 15792 ₽ за 1 / 3 / 6 / 12 месяцев.

При расчётном курсе со скриншота владельца 81,25 ₽/$ и аренде $7,60 / $22,12 / $42,86 / $80,26 остаток после аренды и комиссии составляет 656,50 / 1967,42 / 3932,31 / 7849,60 ₽ соответственно за весь период. Это не чистая прибыль: налоги, поддержка, реклама и дополнительные комиссии вывода/обмена не включены. Курс не обновляется автоматически.
