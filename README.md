# Way VPN Bot

Telegram-бот для продажи персонального VPN: клиент выбирает срок и страну, оплачивает, администратор вручную создаёт подключение и выдаёт ссылку через бот.

## Возможности

- Клиентское меню в два ряда с цветными кнопками.
- Выбор страны перед оплатой; при продлении страна сохраняется.
- RollyPay: создание платежей, проверка подписанных уведомлений, защита от повторной выдачи.
- Оплаченные заявки и уведомления администраторам в Telegram.
- Ручная выдача ссылки и подтверждение выполненного продления.
- Управление ценами, сроками и доступными странами из админки.
- Личный кабинет со ссылкой, сроком и историей заказов.
- Текстовая поддержка и напоминания об окончании подписки.
- SQLite, очередь уведомлений с повторными попытками, Docker и автоматический HTTPS через Caddy.

Бот не создаёт VPN-серверы, не ограничивает устройства и не отключает доступ автоматически. Выделенный адрес, постоянная страна и несколько способов подключения обеспечиваются вашей VPN-инфраструктурой.

## Тарифы

- **1 месяц — 1 400 ₽**.
- **3 месяца — 4 137 ₽**.
- **6 месяцев — 8 148 ₽**.
- **12 месяцев — 15 792 ₽**.

Цены рассчитаны как аренда 700 ₽ плюс наценка 700 ₽ за месяц. Скидки провайдера 3%, 6% и 12% применены только к аренде. Комиссия платёжки 9% удерживается из этих цен, дополнительно клиенту не начисляется. Все цены можно изменить в админке; существующие заказы сохраняют свои условия.

Сроки в боте — календарные месяцы. Если провайдер продаёт периоды по 30 дней, учитывайте разницу при аренде сервера.

## Быстрый деплой на сервер

Понадобятся Linux VPS, Git, Python 3, `flock` (обычно входит в util-linux), Docker Engine и Docker Compose v2 с поддержкой `up --wait`. У пользователя должен быть доступ к Docker. Установка Docker: [официальная инструкция](https://docs.docker.com/engine/install/).

Также нужны:

- Домен с DNS-записью на сервер и свободные порты **80/443**.
- Токен Telegram-бота от BotFather и числовые Telegram ID администраторов.
- Касса RollyPay: API-ключ и секрет подписи уведомлений.

```sh
git clone https://github.com/asdasdasdasdasdasdaadas/way-vpn-bot.git
cd way-vpn-bot
./scripts/deploy.sh
```

При первом запуске скрипт запросит настройки и сохранит их в `.env.production` с правами `600`. Секреты при вводе скрыты. Затем проверит конфигурацию, соберёт контейнер и запустит бот с Caddy. Docker и DNS скрипт не устанавливает и не меняет.

Для запуска без вопросов заранее скопируйте `.env.production.example` в `.env.production` и заполните поля. Не передавайте секреты в аргументах команд и не публикуйте этот файл.

**Перед запуском остановите другую копию бота с тем же токеном**, включая локальную демонстрацию. На одном токене должен работать один процесс получения сообщений.

### Подключение платежей

1. В настройках кассы RollyPay задайте `callback_url=https://ВАШ-ДОМЕН/webhooks/rollypay`.
2. Откройте бот, нажмите `/start`, затем `/admin`.
3. Добавьте реальные доступные страны: **Админка → Локации**. Серверная база создаётся с пустым списком стран.
4. Оставьте `ROLLYPAY_TEST=true` и проверьте тестовую оплату, создание заявки и ручную выдачу ссылки.
5. После проверки измените `ROLLYPAY_TEST=false` в `.env.production` и снова запустите `./scripts/deploy.sh`.

В серверной конфигурации `DEMO_MODE` принудительно выключен. Тестовый режим RollyPay проверяет реальную интеграцию, но не добавляет клиенту действующую подписку. Доступность контейнеров не подтверждает получение HTTPS-сертификата или работу кассы — отдельно проверьте Caddy и тестовый платёж.

Корневой адрес домена возвращает 404: это нормально. Публично открыт только POST `/webhooks/rollypay`.

## Обновление

```sh
./scripts/deploy.sh --update
```

Скрипт требует чистую ветку `main`, сохраняет копию работающей базы, запоминает предыдущий коммит, получает изменения через `git pull --ff-only`, пересобирает контейнер и ждёт проверки здоровья. Если бот уже установлен, но остановлен, скрипт попросит сначала запустить его для резервного копирования. После получения новой версии скрипт перезапускает себя; в ходе обновления могут создаться две резервные копии.

Если сборка упала, работающий контейнер остаётся прежним. Если новая версия не запустилась, скрипт завершится с ошибкой и подскажет команду просмотра логов. Автоматического отката базы нет: он может потерять свежие платежи. Порядок восстановления описан в [инструкции развёртывания](deploy/DEPLOY.md).

## Управление

```sh
# Статус и логи
./scripts/production.sh ps
./scripts/production.sh logs --tail=100 -f bot caddy

# Резервная копия базы
./scripts/backup.sh

# Остановка и повторный запуск
./scripts/production.sh stop
./scripts/production.sh up -d --wait
```

Данные сохраняются в Docker volume. **Не используйте `down -v`** — это удаляет базу и сертификаты. Резервные копии появляются в `backups/`; переносите их в защищённое хранилище вне сервера. Они содержат личные ссылки клиентов.

## Работа администратора

Админка доступна только ID из `ADMIN_IDS` в личном чате. Каждый администратор должен сначала нажать `/start`.

- **Заявки:** возьмите оплаченную заявку, создайте VPN, нажмите «Выдать / заменить ссылку» и отправьте ссылку.
- **Продления:** продлите VPN на сервере, затем подтвердите «Продление выполнено» в заявке.
- **Тарифы:** формат ввода `Название | цена в рублях | число месяцев`, например `VPN — 3 месяца | 4137 | 3`.
- **Локации:** добавляйте страны и отключайте недоступные для новых клиентов. Существующие подписки сохраняют свою страну.
- **Поддержка:** отвечайте клиентам через уведомления; текст сохраняется в базе. Вложения пока не поддерживаются.

Команды: `/start`, `/admin`, `/support`, `/paysupport`, `/cancel`, `/id`.

Первая подписка начинается при выдаче ссылки. Продление добавляется к текущей дате окончания; если срок истёк, начинается с момента выполнения заявки. Напоминания проверяются раз в час. После истечения срока администратор получает сообщение для ручного отключения.

### Сбои оплаты и возвраты

Если RollyPay не ответил при создании платежа, заказ сохраняется для сверки, повторная покупка временно блокируется. В админке откройте «Проверить зависшие оплаты».

- Если платёж найден: `/recover order_id payment_id` сверит его через API.
- Если API не вернул признак тестовой оплаты, запросите повторную доставку подписанного вебхука у RollyPay.
- Только после проверки, что платёж не создан: `/close_unpaid order_id`, затем подтверждение `НЕ СОЗДАН`.

Возврат выполняется через RollyPay. Бот блокирует невыполненную заявку и уведомляет администратора. Уже выданный VPN и срок нужно корректировать вручную. Автоматической полной сверки всех платежей нет; после простоя проверяйте доставку уведомлений в кассе.

## Локальный запуск и тесты

Python 3.9+ на Linux/macOS; контейнер использует Python 3.12.

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

Для локального запуска создайте `.env` по `.env.example`, укажите `DATABASE_PATH=data/bot.sqlite3`, `HOST=127.0.0.1`, затем:

```sh
.venv/bin/python run_local.py
```

Для демонстрации без ключей RollyPay добавьте `DEMO_MODE=true`, `ROLLYPAY_TEST=true` и используйте отдельную базу `DATABASE_PATH=data/demo.sqlite3`. Кнопка имитации оплаты доступна только администратору. Реальных платежей и подписок этот режим не создаёт. Германия, Нидерланды и Финляндия добавляются только как демонстрационный список.

Тесты поднимают локальные HTTP-серверы вместо Telegram/RollyPay. Для полноценной проверки сервера всё равно нужны реальные ключи кассы и тестовый платёж. Инструкции: [deploy/DEPLOY.md](deploy/DEPLOY.md).

Архив исходников без секретов и пользовательских данных:

```sh
python3 scripts/package.py
```

Результат: `dist/vpn-bot-deploy.tar.gz`.

## Правила платформы

Telegram требует использовать Stars для продажи цифровых услуг внутри ботов. Внешняя ссылка RollyPay сама по себе не отменяет это требование. До публичных продаж определите допустимую схему: [правила Telegram](https://core.telegram.org/bots/payments-stars). Реализация платёжного API не означает одобрение такой схемы платформой.

Персональный IP не гарантирует отсутствие блокировок сторонних сервисов. Работа и условия VPN-инфраструктуры находятся вне ответственности этого кода.
